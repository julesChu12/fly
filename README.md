
# Fly Monorepo

**Fly** 是一个采用 Monorepo 模式管理的分布式服务架构项目。  
它的目标是通过清晰的模块边界和共享能力库，加速独立开发者从需求到交付的效率。

---

## 📦 仓库结构

```text
fly/
  go.work
  mora/        # 通用能力库
  custos/      # 用户域（身份 & 权限中心）
  clotho/      # API 编排层
  hermes/      # 客户管理服务
  kratos/      # 订单管理服务 (已完成)
  plutus/      # 支付钱包服务 (已完成)
  appointments/ # 预约管理服务 (新增)
  staff/       # 员工管理服务 (新增)
  observability/ # 可观测性服务
  scripts/     # 脚本工具
```

---

## 🔹 模块说明

### 1. Mora （能力库）

- 定位：框架无关的通用能力库  
- 功能：JWT/JWK、日志、配置、数据库、缓存、消息队列、工具方法  
- 特点：不依赖业务逻辑，可被所有服务使用  

### 2. Custos （用户域）

- 定位：身份与权限中心  
- 功能：用户表、账号体系、本地/外部 OAuth2.0 登录、内部 Token 签发、RBAC、强制下线  
- 特点：唯一 Token 签发者，其他服务只消费 Custos Token  

### 3. Clotho （API 编排层）

- 定位：对外统一 API 门面  
- 功能：Token 校验、请求编排、聚合结果返回  
- 特点：不签发 Token，只做编排和网关逻辑  

### 4. Hermes (客户服务)

- 定位：客户信息与联系方式管理中心
- 功能：客户 CRUD、联系方式管理、双协议支持 (HTTP + gRPC)
- 特点：集成 DTM 分布式事务、支持链路追踪与缓存

### 5. Kratos (订单服务)

- 定位：订单生命周期管理中心
- 功能：订单创建、状态机管理、订单项管理、审计日志
- 特点：完整的状态流转控制、多租户数据隔离、双协议支持

### 6. Plutus (支付钱包服务)

- 定位：支付与钱包基座服务
- 功能：钱包账户管理、交易流水、充值/消费/退款、支付渠道集成
- 特点：事务一致性保障、幂等性支持、完整的资金流审计

### 7. Appointments (预约管理服务)

- 定位：预约调度与时间管理中心
- 功能：预约创建、状态流转、冲突检测、可用时间查询、日历视图
- 特点：智能时间冲突检测、灵活的提醒机制、完整的预约生命周期管理

### 8. Staff (员工管理服务)

- 定位：员工信息与权限管理中心
- 功能：员工 CRUD、角色管理、可用性设置、技能标签、组织架构
- 特点：灵活的角色���限系统、员工可用性管理、完整的职业生命周期跟踪

## 🔹 架构原则

1. **分层清晰**：Mora → Custos → Clotho → 业务域
2. **统一 Token 签发**：所有身份认证由 Custos 管理
3. **API 门面统一**：Clotho 是唯一对外暴露层
4. **开发友好**：Monorepo + go.work，保证多模块协作丝滑
5. **服务自治**：每个业务域服务独立部署，通过 HTTP/gRPC 通信
6. **数据一致性**：服务间采用最终一致性，关键业务使用分布式事务
